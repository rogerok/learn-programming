# Оси асинхронности

## Flow: push, pull

- Pull: значение появляется, когда потребитель попросил. Источник пассивен: итератор, генератор, for await
- Push: источник отправляет значения сам, когда оно готово, а потребитель реагирует на него. `addEventListener`, `EventEmitter`, WebSocket сообщение


В режиме pull очередь никогда не растёт: на каждый `next()` ровно один шаг, темп задаёт потребитель.
В режиме push продюсер эмитит, когда хочет. Если потребитель не успевает забирать - очередь разрастается.
У голого push **нет встроенного тормоза**

## Propagation: push, pull, hybrid

Чистый pull (async iterable) распространяет ошибку как обычный `throw`: летит вверх по `for await`, 
останавливает итерацию, ловится в `try/catch`. Отмена через `iterator.return()`, когда потребитель вышел по g `break`

Чистый push - не имеет встроенного канала ошибок. Ошибку приходится отдавать отдельным событием `error`. Если на него никто не подписан, в Node это роняет процесс.
Отмена тоже внешняя `removeEventListener`, `AbortSignal`

Гибрид, это потоки с back-pressure, источник пушит, но обязан остановиться, если потребитель потребует.
 Ошибка тут распространяется по конвейеру: упавший этап pipeThrough рвёт всю цепочку и отдаёт ошибку в pipeTo.

```ts
// hybrid: источник пушит, но конвейер держит давление
await source
  .pipeThrough(decompress) // упадёт здесь
  .pipeThrough(parse)
  .pipeTo(sink); // ошибка прилетит сюда, цепочка закроется
```

## State-ownership

- Exclusive: один владелец, никто больше не пишет
- Shared: несколько задач пишут в общее
- Isolated: у каждого своё состояние
- Cooperative: задачи уступают доступ в известных точках. Так устроен event loop
- Transactional : изменения копятся и применяются атомарно, при конфликте повтор


## Eagerness: eager против lazy

Eager, это Promise. Как только ты написал fetch(url), запрос уже пошёл, ещё до await. Промис нельзя перезапустить, у него один результат, зафиксированный навсегда.

Lazy, это Task, Observable, Effect. Ты описываешь, что должно произойти, но ничего не происходит, пока кто-то не подпишется или не запустит. Поэтому ленивое значение можно перезапускать, ретраить, комбинировать как обычное значение.
