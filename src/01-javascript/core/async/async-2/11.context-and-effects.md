# Контекст и модели: AsyncLocalStorage, акторы, STM, Effect


## Актор 

Актор - сущность с приватным состоянием и mailbox. Снаружи в него нельзя записать, только послать сообщение.
Сообщения обрабатываются по одному, состояние не разделяется, mailbox обрабатывается последовательно, гонок внутри акторах нет по построению.

В JS акторы ложатся на worker-ы. Каждый worker это изолят со своей памятью, а `postMessage` это и есть отправка mailbox.

Псевдокод актора поверх worker_threads

```ts
class CounterActor {
    #count = 0;
    
    receiver(messsage: {type: 'inc'} | {type: 'get'}): number | void {
        if(message.type === 'inc') this.#count +=1;
        if(message.type === 'get') return thisthis.#count
    } 
}
```

Т.е. изолированное состояние + обмен сообщениями. Такая акторная архитектура дотягивается до `request-reply`, `pub-sub`, CQRS.


## STM
Software Transaction Memory - изменения над общими ячейками копятся в транзакции и применяются атомарно.
Если за время транзакции кто-то изменил данные, транзакция откатывается и повторяется.

```ts
import {Effect, STM, TRef} from 'effect';

const transfer = (from: TRef.Tref<number>, to: TRef.Tref<number>, amount: number) => STM.gen(function* () {
    const balance = yield* TRef.get(from);
    
    if(balance < amount) return yield* STM.fail('недостаточно средств')
    yield* TRef.set(from, balance - amount);
    yield* TRef.update(to, (value) => value + amount);
})
await Effect.runPromise(STM.commit(transfer(accountA, accountB, 50)));
```

Плюс STM в композиции - две транзакции можно сцепить в одну большую, и она останется атомарной.
