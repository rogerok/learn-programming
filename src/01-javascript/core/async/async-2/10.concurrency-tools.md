# Инструменты конкурентности · очереди, семафоры, гонки

Для того чтобы избежать race condition, существует несколько вариантов решений


## Mutex, Semaphore, RWLock

### Mutex

Mutex пропускает в защищенный участок ровно одного, а остальные ждут.

```ts
class Mutex {
  private locked = false;
  private waiters: Array<() => void> = []; // ресоловы промиса. каждую ф-цию можно вызвать позже, чтобы "разбудить" ожидающий acquire();

  async acquire(): Promise<void> {
    // Проверяем свободен ли mutex, если свободен, сразу захватываем его
    if (!this.locked) {
      this.locked = true;
      return; // выходим из acquire, ждать не нужно
    }

    /*
     * Если mutex занят - создаем промис, берем его resolve и кладем в очередь waiters. Текущий вызов засыпает на await,
     * и будет ждать, пока кто-то вызовет этот resolve
     * */

    await new Promise<void>((resolve) => this.waiters.push(resolve));
  }

  // Метод освобождения mutex.

  release(): void {
    // Берём первого ожидающего из очереди
    const next = this.waiters.shift();

    // Если кто-то ждал, то вызываем его resolve. Это разблокирует await внутри его acquire
    if (next) next();
    /* ВАЖНО
     * locked не становится false, mutex остается занятым, просто владение передается следующему ожидающему
     * */ else this.locked = false;
  }
}
```

### Пример использования: защита общей переменной

Представь, что есть общий счетчик `balance`. Несколько асинхронных операций одновременно читают его значение, отправляют условный запрос в сеть, а потом записывают новое значение.

Без защиты легко получить race condition:

```ts
let balance = 0;

function fakeNetworkRequest(): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, 100));
}

async function addMoney(amount: number, name: string) {
  const currentBalance = balance;

  console.log(`${name}: прочитал balance = ${currentBalance}`);

  await fakeNetworkRequest();

  balance = currentBalance + amount;

  console.log(`${name}: записал balance = ${balance}`);
}

addMoney(100, "A");
addMoney(100, "B");
```

Что может произойти:

```txt
A: прочитал balance = 0
B: прочитал balance = 0
A: записал balance = 100
B: записал balance = 100
```

Обе операции прочитали старое значение `0`, поэтому итоговый `balance` стал `100`, хотя мы ожидали `200`.

Теперь защитим участок кода через `Mutex`:

```ts
const mutex = new Mutex();
let balance = 0;

function fakeNetworkRequest(): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, 100));
}

async function addMoney(amount: number, name: string) {
  await mutex.acquire();

  try {
    const currentBalance = balance;

    console.log(`${name}: прочитал balance = ${currentBalance}`);

    await fakeNetworkRequest();

    balance = currentBalance + amount;

    console.log(`${name}: записал balance = ${balance}`);
  } finally {
    mutex.release();
  }
}

addMoney(100, "A");
addMoney(100, "B");
```

Теперь порядок будет таким:

```txt
A захватывает mutex
A читает balance = 0
B пытается захватить mutex и ждет
A записывает balance = 100
A освобождает mutex
B захватывает mutex
B читает balance = 100
B записывает balance = 200
B освобождает mutex
```

Критическая секция здесь:

```ts
const currentBalance = balance;
await fakeNetworkRequest();
balance = currentBalance + amount;
```

Именно этот участок нельзя выполнять параллельно, потому что он работает с общим изменяемым состоянием.

> [!important]
> `release()` нужно вызывать в `finally`, а не просто в конце `try`. Если внутри критической секции произойдет ошибка, `finally` все равно освободит mutex. Иначе все следующие операции зависнут на `await mutex.acquire()`.

Ключевая идея: `Mutex` не ускоряет код. Он специально делает часть кода последовательной, чтобы сохранить корректность данных.



### Semaphore
Семафор это обобщение: пропускает не одного, а до N. Mutex - семафор с лимитом 1.


### RWLock 
Блокировка с двумя режимами.
Читателей внутри может быть сколько угодно одновременно, писатель заходит строго один и только когда вышли все читатели


## Очереди, пулы, коллекторы

AsyncQueue буфер между быстрым источником и медленным потребителем.
Потребитель тянет через `await queue.next()`, а если пусто, ждёт.

Пул - это N исполнителей, разбирающих задачи из общей очереди.
Освободился, взял следующую.

Коллектор - собирает значения из многих источников, пока не выполнится условие (набралось N, выполнился предикат и т.п.), и отдать пачкой.
