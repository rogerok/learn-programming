# Установка и настройка

## 1. Выберите область установки

OMP обнаруживает определения агентов из двух основных мест:

- пользовательские, доступные во всех проектах: `~/.omp/agent/agents/`;
- проектные, доступные только в конкретном репозитории: `<repo>/.omp/agents/`.

Проектные определения имеют приоритет над пользовательскими при совпадении точного имени агента.

### Пользовательская установка

Из каталога `src/agents`:

```bash
mkdir -p ~/.omp/agent/agents
cp definitions/*.md ~/.omp/agent/agents/
```

### Установка в один проект

Из корня нужного репозитория, где `<path-to-kit>` — путь к этому каталогу:

```bash
mkdir -p .omp/agents
cp <path-to-kit>/definitions/*.md .omp/agents/
```

Не копируйте туториалы в `.omp/agents`: каждая Markdown-запись в каталоге определений рассматривается как кандидат на агента.

## 2. Назначьте модели ролям

Определения используют две роли:

- `@smol` — дешёвое исследование, классификация и выполнение узких сценариев;
- `@task` — более надёжная, но всё ещё недорогая coding-модель для edits и review.

Назначить их проще всего через `/models`. Выбирайте модели, которые:

1. доступны через настроенного провайдера;
2. устойчиво вызывают инструменты;
3. имеют контекст, достаточный для одного ограниченного среза;
4. стоят заметно дешевле основной модели.

Альтернатива — перенести `modelRoles` из [`../config/model-roles.example.yml`](../config/model-roles.example.yml) в активный OMP config. Строки `provider/...` в примере являются заполнителями: замените их точными селекторами из `/models` или `omp models`.

### Почему используются роли

Если модель задана прямо в каждом агенте, смена провайдера требует редактировать все определения. Роли дают одну точку переключения:

```text
cheap-scout       → @smol
cheap-librarian   → @smol
cheap-verifier    → @smol
cheap-worker      → @task
cheap-reviewer    → @task
```

## 3. Убедитесь, что агенты обнаружены

Перезапустите или обновите сессию OMP после копирования файлов. В интерфейсе агентов должны появиться:

```text
cheap-scout
cheap-librarian
cheap-worker
cheap-reviewer
cheap-verifier
```

Если агент не виден, проверьте:

- файл находится именно в `.omp/agents` или `~/.omp/agent/agents`;
- YAML frontmatter начинается и заканчивается строкой `---`;
- `name` и `description` присутствуют;
- имя не отключено в `task.disabledAgents`;
- родительской сессии разрешён spawn этого типа агента;
- селектор модели из `model` разрешается в доступную модель.

## 4. Первый безопасный тест

Запросите исследование без edits:

```text
Параллельно отправь двух cheap-scout:
1. найти entry points приложения;
2. найти границы persistence и основные модели данных.
Каждый должен вернуть точные file:line и unknowns.
Сам сопоставь отчёты, проверь одно критичное утверждение через LSP
и составь краткую карту системы. Ничего не изменяй.
```

Проверьте результат:

- было создано два независимых задания;
- каждый отчёт содержит пути и символы;
- основная модель не приняла спорный вывод без проверки;
- файлы репозитория не менялись.

## 5. Первый тест с edit

Выберите механическую задачу в учебном или временном репозитории:

```text
Сначала сам определи точный контракт изменения и список допустимых файлов.
Затем передай один независимый срез cheap-worker.
Запрети менять публичные интерфейсы и конфигурацию.
После его завершения сам проверь diff по смыслу и запусти узкий сценарий.
```

`cheap-worker` намеренно требует полный контракт. Если задание размыто, правильный результат агента — блокирующий отчёт, а не выдуманное решение.

## 6. Настройка цены и качества

Начальная конфигурация:

| Роль | Thinking | Применение |
|---|---:|---|
| `@smol` | low | поиск, инвентаризация, внешние источники, запуск заданного сценария |
| `@task` | medium | локальные edits, review сложного потока |
| основная модель | high/max по необходимости | контракт, архитектура, интеграция, итог |

Если дешёвый агент часто теряет call sites, сначала уменьшите scope одного задания. Повышайте модель только когда узкое и полное задание всё равно выполняется ненадёжно.
