Что означает принцип parse-don't-validate?	На границе доверия один раз превращаем unknown в типизированное значение. Дальше код работает с доказанным типом и не повторяет проверки повсюду.	effect-ts::schema::parse-dont-validate
Где обычно находится граница доверия для Schema?	Там, где данные приходят извне: JSON.parse, HTTP body, env variables, конфиги, файлы, ответы внешних API.	effect-ts::schema::boundary
Какие две стороны есть у Effect Schema?	Encoded — сырая wire/JSON-форма. Type — богатая внутренняя форма после decode.	effect-ts::schema::encoded-type
Что делает decode в модели Encoded -> Type?	Проверяет внешнее значение и при успехе возвращает внутренний Type, с которым безопасно работает приложение.	effect-ts::schema::decode
Что делает encode в модели Type -> Encoded?	Берёт внутреннее значение Type и превращает его в wire-форму для JSON, HTTP, файла или базы данных.	effect-ts::schema::encode
Когда Encoded и Type совпадают?	Когда схема не делает преобразований: например, Schema.String или Struct только из простых примитивов.	effect-ts::schema::encoded-type
Когда Encoded и Type различаются?	Когда есть transform, brand, Date, Duration, URL, Option или другая богатая внутренняя модель.	effect-ts::schema::encoded-type
Что возвращает Schema.decodeUnknown(S)(value)?	Effect с успешным Type схемы и ParseError в канале E. Для чистых схем R обычно равен never.	effect-ts::schema::decodeUnknown
Когда удобен Schema.decodeUnknown, а не sync-вариант?	Когда ты уже находишься в Effect-коде и хочешь пустить ошибку парсинга через общий E-канал.	effect-ts::schema::decodeUnknown
Когда уместен Schema.decodeUnknownSync?	В тестах, скриптах или местах старта, где ошибка парсинга должна сразу броситься как исключение и остановить выполнение.	effect-ts::schema::decodeUnknownSync
Как получить Type из схемы Monitor?	Через Schema.Schema.Type<typeof Monitor>. Это тип значения после успешного decode.	effect-ts::schema::types
Как получить Encoded из схемы Monitor?	Через Schema.Schema.Encoded<typeof Monitor>. Это тип внешней формы до decode и после encode.	effect-ts::schema::types
Что даёт Schema.Struct?	Декларативно описывает runtime-форму объекта, выводит TypeScript-тип и строит структурированные ParseError при ошибках.	effect-ts::schema::struct
Почему Schema.Struct лучше ручной лестницы typeof-проверок?	Схема описывается один раз, переиспользуется для decode/encode, выводит типы и даёт нормальные ошибки с путями до полей.	effect-ts::schema::struct
Что такое ParseError в Effect Schema?	Структурированная ошибка парсинга, где можно увидеть путь до проблемного поля и нарушенное ожидание.	effect-ts::schema::errors
Зачем нужны TreeFormatter или ArrayFormatter?	Они превращают ParseError в читаемый отчёт, пригодный для логов, CLI или сообщения пользователю.	effect-ts::schema::errors
Что означает ошибка на пути monitors[1].interval?	Сломалось поле interval у второго элемента массива monitors; искать проблему нужно в этой точке входных данных.	effect-ts::schema::errors
Что даёт optionalWith(Schema.Number, { as: "Option" })?	Encoded-сторона разрешает отсутствие поля, а Type-сторона получает Option<number> вместо undefined/null.	effect-ts::schema::option
Почему Option лучше, чем null | undefined по всему коду?	Option заставляет явно обработать Some и None, а null/undefined легко протекают дальше и требуют разрозненных проверок.	effect-ts::schema::option
Что такое Schema.TaggedStruct?	Короткая запись структуры с дискриминатором _tag и заданными полями. Удобна для tagged unions событий и ошибок.	effect-ts::schema::tagged-struct
Как собрать union из нескольких tagged-событий?	Через Schema.Union(EventA, EventB, EventC). По _tag TypeScript потом сможет сужать конкретную ветку.	effect-ts::schema::union
Что проверяет round-trip decode(encode(x)) === x?	Что внутреннее Type-значение после сериализации и обратного парсинга не теряет смысл.	effect-ts::schema::round-trip
Что проверяет wire-trip encode(decode(j)) === j?	Что внешняя wire-форма после decode и encode возвращается в ожидаемый внешний формат.	effect-ts::schema::round-trip
Когда использовать Schema.transform?	Когда переход между Encoded и Type не должен падать и обе функции могут вернуть обычное значение.	effect-ts::schema::transform
Когда использовать Schema.transformOrFail?	Когда decode или encode может провалиться и нужно вернуть ParseResult.succeed или ParseResult.fail.	effect-ts::schema::transformOrFail
Почему decode-функция внутри transform не принимает unknown?	fromSchema уже распарсила вход. В decode приходит значение типа from-стороны, например уже string.	effect-ts::schema::transform
Что делает Schema.filter?	Добавляет runtime-условие к существующему типу: непустая строка, int, диапазон, pattern и т.п.	effect-ts::schema::filter
Меняет ли Schema.filter TypeScript-тип на nominal type?	Нет. После filter TypeScript по-прежнему видит обычный string/number. Для nominal typing нужен brand.	effect-ts::schema::filter::brand
Что делает Schema.brand?	Помечает Type-сторону фантомным nominal-типом, чтобы нельзя было случайно передать обычную строку туда, где нужен проверенный доменный id/url.	effect-ts::schema::brand
Что происходит с brand на runtime?	В JavaScript остаётся обычное значение. Brand существует на уровне TypeScript-типа и не добавляет runtime-объект.	effect-ts::schema::brand
Когда Schema.brand подходит лучше, чем Schema.Class?	Когда нужен сильный тип над примитивом string/number без методов, конструктора и instanceof.	effect-ts::schema::brand::class
Когда выбрать Schema.Class вместо brand?	Когда значение структурное и ему нужны методы, constructor behavior или проверка instanceof.	effect-ts::schema::class
Что даёт Schema.pick / Schema.omit?	Позволяет строить DTO и CRUD-схемы из базовой схемы без ручного дублирования полей.	effect-ts::schema::composition
Что делает Schema.compose?	Соединяет transform-схемы в pipeline: decode идёт слева направо, encode — в обратную сторону.	effect-ts::schema::compose
Зачем нужны Schema.typeSchema и Schema.encodedSchema?	typeSchema оставляет уже декодированную Type-сторону, encodedSchema — внешнюю wire-сторону. Это полезно для разных видов тестов и моков.	effect-ts::schema::projection
Что даёт optionalWith с default?	Внешнее поле может отсутствовать, а внутри программы после decode значение уже обязательно и имеет дефолт.	effect-ts::schema::defaults
Чем optionalWith default отличается от withConstructorDefault?	optionalWith default работает при decode внешних данных, а withConstructorDefault — при программном создании значения через make/constructor.	effect-ts::schema::defaults
Что означает R в Schema<A, I, R>?	Зависимости, которые нужны схеме для decode/encode. В чистых схемах R = never.	effect-ts::schema::context
Когда у схемы появляется ненулевой R?	Когда transformOrFail возвращает Effect, которому нужен сервис, например Clock, локальный кэш или другой Layer dependency.	effect-ts::schema::effectful-transform
Почему не стоит ходить в сеть или БД внутри transformOrFail?	Парсинг должен быть быстрым, предсказуемым и близким к границе данных. Сеть/БД превращают схему в бизнес-логику и усложняют тестирование.	effect-ts::schema::anti-pattern
Главный вопрос при чтении чужой Schema?	Какая у неё Encoded-сторона, какая Type-сторона, и какие проверки/трансформации стоят между ними.	effect-ts::schema::reading
