# Resources: Scope, finalizers, acquireRelease, forkScoped, graceful shutdown

## Finalizers

### Effect.ensuring

Аналог `finally`. Принимает один `Effect`, выполняет его всегда, не имеет доступа к исходу.

```ts
import { Effect } from 'effect';

const program = Effect.gen(function* () {
    yield* Effect.sleep('1 second');
}).pipe(Effect.ensuring(Effect.log('done')))

Effect.runPromise(program) 
// done
```

Падение через `Effect.dieMessage`:


```ts
const program = Effect.gen(function* () {
    yield* Effect.dieOnMessage('Boom')
}).pipe(Effect.ensuring(Effect.log('done')));

Effect.runPromise(program);

// done
// program rejects with FiberFailure: Boom
```

Отработал при падении тоже. Его контракт запустить cleanup в любом случае.

### `Effect.onError`

Если cleanup нужен только на провале, используем `Effect.onError`

```ts
const program = Effect.gen(function* () {
    yield* Effect.fail('boom')
}).pipe(Effect.onError((cause) => Effect.log(`cleanup: ${cause}`) ))

Effect.runPromise(program)
// cleanup: Error: boom
// (program rejects)
```
На успехе колбэк не вызывается.



### `Effect.onExit` +  `Exit.match`

Когда нужен полный исход - успех или провал, со значением или причиной, берем `Effect.onExit`

```ts
const program = Effect.gen(function* () {
    yield* Effect.fail('boom');
}).pipe(Effect.onExit(
    Effect.match({
        onSuccess: (v) => Effect.log(`ok: ${v}`),
        onFailure: (cause) => Effect.log(`error: ${cause}`)
    })
))

Effect.runPromise(program)
```

`Exit.match`  идеально ложится в `pipe`. У него два коллбэка `onSuccess`, `onFailure`.


В итоге, если cleanup не зависит от исхода и нам не нужен `Exit` - берем `ensuring`, если важен `Exit` - берем `onExit`


### `Effect.onInterrupt`
Cleanup только на прерывание.
Прерывание - отмена fiber-а извне.

Effect выполняет её кооперативно: рантайм проверяет флаг прерывания на каждом yield. 
Прерывание это не ошибка из канала E и не defect, это третий тип исхода. На уровне Cause оно представлено Cause.interrupt.

```ts
const program = Effect.gen(function* () {
    yield* Effect.sleep('5 ceonds')
}).pipe(Effect.onInterrupt((interruptors) => Effect.log(`interrupted by ${[...interruptors]}`)));
```

## Scope


Scope позволяет использовать несколько финалайзеров.
Например, запрос открывает три ресурса, каждый из них должен быть закрыт. Можно сложить три `Effect.ensuring`, но порядок закрытия сломается.

Scope это явное ведро для финалайзеров. Его создают, регистрируют финалайзеры и потом закрывают.
Effect выполняет все финалайзеры в обратном порядке.

Свойства финалайзеров:
1) Получают `Exit`: можно различить успех, провал, прерывание, как в `Effect.onExit`
2) Идут в обратном порядке (LIFO). Позже зарегистрированный finalizer выполняется первым, чтобы соблюсти зависимости

### Создаём руками

```ts
import {Effect, Exit, Scope} from 'effect';


const program = Effect.gen(function* () {
    const scope = yield* Scope.make();
    
    yield* Scope.addFinalizer(scope, Effect.log('closing network connection'));
    yield* Scope.addFinalizer(scope, Effect.log('closing remote file'))
    
    yield* Effect.log('work done');
    
    yield* Scope.close(scope, Exit.void) 
})
Effect.runPromise(program);
// work done
// closing remote file
// closing network connection
```

`Scope.addFinalizer` принимает не ф-цию, а готовый эффект. Если нужен динамический финализатор, его нужно заворачивать в `Effect.gen` или в `Effect.suspend`

Scope.close(scope, exit) запускает finalizer-ы.


### При ручном `Scope.close` возможна утечка

Если между `Scope.make` и `Scope.exit` эффект упал, то финалайзеры упадут, потечет память.

### Свой `scoped`

```ts
const scoped = <A, E, R>(self: Effect.Effect<A, E,R>): Effect.Effect<A,E, Exclude<R, Scope.Scope>> => Effect.gen(function* () {
    const scope = yield* Scope.make();

    // кладём scope в контекст эффекта
    const extended = yield* Scope.extend(self, scope); 
    
    // Закрыть scope ровно одним исходом, на завершении extended
    return yield* Effect.onExit(extended, (exit) => Scope.close(scope, exit));
})
```

Тип возврата: `Effect<A, E, Exclude<R, Scope>>` убирает Scope из требований, но прочие (например `HttpService`) сохраняем.

```ts
const program = Effect.gen(function* () {
    yield* Effect.addFinalizer((exit) => Effect.log(`closing network connection (${exit._tag})`));
    yield* Effect.addFinalizer((exit) => Effect.log(`closing remote file (${exit._tag})`));

    yield* Effect.dieMessage('Boom');
    
    yield* Effect.log('work done')
}).pipe(scoped);

Effect.runPromise(program);

// closing remote file (Failure);
// closing network connection (Failure);
// (program rejects with FiberFailure: Boom)
```
Финалайзеры отработали оба и в правильном порядке.

### `Effect.scoped`

```ts
const program = Effect.gen(function* () {
    yield* Effect.addFinalizer((exit) => Effect.log(`closing network connection (${exit._tag})`));
    yield* Effect.addFinalizer((exit) => Effect.log(`closing remote file (${exit._tag})`));
    
    yield* Effect.dieMessage('Boom');
}).pipe(Effect.scoped);

Effect.runPromise(program)
```

## `acquireRelease`, `acuireUseRelease`

Рядом с финалайзером всегда живет acquire, шаг приобретения ресурса.
Для пары acquire-release Effect даёт два специальных комбинатора.


Вводный пример

```ts
type ReportHandle = {read: () => Promise<string>; close: () => Promise<void>}

declare const openReport: Effect.Effect<ReportHandle, never, never>;
declare const closeReport: (handle: ReportHandle) => Promise<void>;
```

### Ручной способ

```ts
const program = Effect.gen(function* () {
    const handle = yield* openReport; // это acquire 
    
    yield* Effect.addFinalizer(() => Effect.promise(() => closeReport())) // это release
})
```
acquire и release разнесены на две строки, связаны только переменной `handle`. Можно случайно не выполнить один из двух шагов, в типе программы виден Scope, но не видна пара acquire-release.


### `Effect.aquireRelease`

```ts
const reportResource = Effect.acquireRelease(
    openReport, (handle, exit) => Effect.promise(() => closeReport(handle))
);
// reportResource: Effect<ReportHandle, never, Scope>
```
Release знает `exit`. В зависимости от исхода можно писать в журнал или ретраить.
acquire и release склеены, невозможно случайно зарегистрировать одно без другого.

Использование

```ts
const program = Effect.gen(function* () {
    const handle = yield* reportResource;
    const data = yield* Effect.promise(() => handle.read());
    yield* Effect.log(`got ${data.length} bytes`);
}).pipe(Effect.scoped);
```

`Effect.scoped` закрывает scope на исходе, `aquireRelease` регистрирует release


### `Effect.acquireUseRelease`

Когда ресурс нужен **строго на одну операцию** и тащить его как переменную лень, используй `Effect.acquireUseRelease`.

Принимает три аргумента: acquire, use (ф-ция т ресурса в эффект), release

```ts
const program = Effect.acquireUseRelease(
    openReport,
    (handle) => Effect.gen(function* () {
        const data = yield* Effect.promise(() => handle.read());
        yield* Effect.log(`got ${data.length} bytes`)
        return data
    }), 
    (handle, exit) => Effect.promise(() => closeReport(handle))
)
// program: Effect<string, never, never>
```

`R = never`, `acquireUseRelease` не требует Scope на выходе, потому что ресурс живет внутри use и закрывается прям там.
`Effect.scoped` снаружи не нужен.

`acquireRelease` отдаёт ресурс, тип отражает только ресурс. Если внутри `Effect.gen` упадём на парсинге тела, это ошибка вызывающего кода, а не ресурса.

`acquireUseRelease` отдаёт результат `use` и тип отражает что угодно, что в use может случиться. 

В обоих случаях release **гарантированно отрабатывает**, даже при падении.
