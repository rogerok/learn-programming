Что такое сервис в Effect-TS?	Сервис — это типизированный контракт зависимости: тег плюс форма методов, которые программа может запросить из окружения R.	effect-ts::services
Что такое Layer в Effect-TS?	Layer — рецепт сборки сервиса или графа сервисов с зависимостями, мемоизацией и управлением ресурсами.	effect-ts::layer
Какую роль играет R в dependency injection Effect?	R показывает, какие сервисы нужны программе. Пока R не закрыт до never, программу нельзя безопасно запустить обычным runtime entry point.	effect-ts::environment::r
Почему DI в Effect типобезопасен?	Недостающие зависимости видны в типе R и ловятся компилятором, а не всплывают как runtime-ошибка контейнера.	effect-ts::di
Что такое prop drilling зависимостей?	Протаскивание зависимости через несколько функций только ради нижнего уровня, который действительно ей пользуется.	effect-ts::di::prop-drilling
Какую проблему решает DI по сравнению с ручной передачей зависимостей?	Промежуточные функции не обязаны принимать и передавать сервисы, которыми сами не пользуются; зависимость остаётся в R потребителя.	effect-ts::di
Что задаёт строка в Context.Tag("Pulse/HttpService")?	Runtime-идентификатор сервиса в Context. По нему Effect различает сервисы внутри окружения.	effect-ts::context-tag
Почему имя Context.Tag должно быть уникальным?	Одинаковый runtime-идентификатор у разных сервисов может привести к конфликтам в Context.	effect-ts::context-tag
Что описывает Shape в Context.Tag<Self, Shape>?	Форму сервиса: readonly-поля и методы, которые получит код, запросивший сервис.	effect-ts::context-tag
Зачем первый generic Context.Tag ссылается на сам сервис?	Он связывает тег с типом требования в R, чтобы TypeScript корректно выводил Effect<A, E, HttpService>.	effect-ts::context-tag
Как достать сервис внутри Effect.gen?	Через yield* Service, например const http = yield* HttpService. После этого требование сервиса появляется в R программы.	effect-ts::context-tag::access
Что делает Effect.provideService(Tag, impl)?	Подкладывает готовую реализацию сервиса и убирает этот Tag из R программы.	effect-ts::provide
Когда использовать Effect.provideServiceEffect?	Когда реализация сервиса строится эффектно: нужна инициализация, чтение конфига, логирование, открытие соединения или ожидаемая ошибка сборки.	effect-ts::provide
Что такое effectful constructor сервиса?	Конструктор, который возвращает Effect со значением сервиса, а не готовый объект сразу.	effect-ts::services::constructor
Как читать тип Layer<ROut, E, RIn>?	ROut — какие сервисы слой строит, E — чем может упасть сборка, RIn — какие зависимости нужны для сборки слоя.	effect-ts::layer::type
Чем Layer отличается от provideServiceEffect?	Layer участвует в графе зависимостей и мемоизирует сборку. provideServiceEffect подаёт эффектный сервис локально без полноценного Layer-графа.	effect-ts::layer
Что делает Layer.effect(Tag, ctor)?	Создаёт Layer, который строит сервис Tag через эффектный конструктор ctor.	effect-ts::layer::effect
Что делает Layer.succeed(Tag, value)?	Создаёт Layer из уже готового синхронного значения сервиса.	effect-ts::layer::succeed
Как подать Layer программе?	Через Effect.provide(layer): Layer закрывает требования программы в R.	effect-ts::provide
Как подать зависимость одному Layer-у?	Через Layer.provide(depLayer): входные требования RIn основного слоя закрываются другим слоем.	effect-ts::layer::provide
Главное различие Effect.provide и Layer.provide?	Effect.provide подаёт Layer программе. Layer.provide подаёт зависимость другому Layer-у при сборке графа.	effect-ts::provide
Почему цепочка нескольких Effect.provide может быть проблемой?	Она может создать отдельные scope/MemoMap и пересобрать общие зависимости несколько раз.	effect-ts::provide::anti-pattern
Как правильно подать несколько Layer-ов программе?	Собрать общий граф через Layer.mergeAll(...) или передать несколько слоёв одним provide-путём, чтобы зависимости делили MemoMap.	effect-ts::layer::merge-all
Что делает Layer.mergeAll?	Объединяет несколько Layer-ов в один граф, где одинаковые Layer-ссылки могут быть построены один раз и переиспользованы.	effect-ts::layer::merge-all
Когда использовать Layer.fresh?	Когда сознательно нужны разные экземпляры одного и того же Layer-а, например два независимых database pool.	effect-ts::layer::fresh
Почему Layer.fresh нельзя ставить "на всякий случай"?	Он отключает полезную мемоизацию и может создать лишние подключения, файлы или фоновые процессы.	effect-ts::layer::fresh
Что такое dependency leak в сервисе?	Метод сервиса внутри себя запрашивает другую зависимость через yield*, и эта зависимость всплывает наружу в R метода.	effect-ts::services::dependency-leak
Какое главное правило против dependency leak?	Глобальные зависимости брать в конструкторе Layer-а, а методы должны использовать уже замкнутые значения.	effect-ts::services::dependency-leak
Когда зависимость допустимо брать внутри метода сервиса?	Когда это request-scoped значение, известное только на конкретном вызове: CurrentUser, RequestId, CurrentMonitor.	effect-ts::services::request-scoped
Почему request-scoped зависимость нельзя брать в глобальном конструкторе Layer-а?	Конструктор выполняется один раз на runtime, поэтому значение заморозится и будет ошибочно переиспользоваться для всех запросов.	effect-ts::services::request-scoped
Что делает Layer.provideMerge(dep)?	Подаёт dep основному Layer-у и одновременно оставляет dep доступным снаружи в итоговом ROut.	effect-ts::layer::provide-merge
Когда нужен Layer.provideMerge вместо Layer.provide?	Когда зависимость нужна и для сборки сервиса, и внешней программе напрямую.	effect-ts::layer::provide-merge
Чем Effect.Service удобнее Context.Tag плюс отдельный Layer?	Он одновременно объявляет тег, выводит форму сервиса, создаёт Default Layer и поддерживает dependencies.	effect-ts::effect-service
Для каких сервисов подходит Effect.Service?	Для глобальных сервисов с канонической реализацией, которые строятся один раз на runtime.	effect-ts::effect-service
Для чего Effect.Service не подходит?	Для request-scoped значений вроде CurrentUser или CurrentMonitor, у которых нет одного глобального экземпляра.	effect-ts::effect-service
Что делает dependencies в Effect.Service?	Закрывает зависимости конструктора указанными Layer-ами, чтобы Default Layer был самодостаточнее.	effect-ts::effect-service
Когда выбрать scoped-конструктор сервиса?	Когда сервис открывает ресурс или запускает процесс, который должен закрыться вместе со Scope.	effect-ts::scope
Что такое default services в Effect?	Сервисы вроде Clock, Random, Console, Tracer, которые runtime предоставляет автоматически и которые обычно не появляются в R.	effect-ts::default-services
Почему Clock.currentTimeMillis не добавляет Clock в R?	Clock — default service, поэтому runtime уже умеет предоставить его без явного Layer.	effect-ts::default-services
Что такое accessor в Effect?	Готовая функция, которая достаёт сервис и вызывает его метод, например Clock.currentTimeMillis.	effect-ts::accessors
Почему accessors: true на своих сервисах может быть опасен?	Accessor скрывает yield* Service внутри метода и может незаметно протащить зависимость наружу в R.	effect-ts::accessors
Что делает Effect.serviceOption(Tag)?	Пытается достать сервис из Context как Option и не добавляет Tag в R, если сервиса нет.	effect-ts::optional-services
Когда выбирать Context.Reference?	Для optional-инфраструктурных сервисов с разумным defaultValue, которые можно использовать без явного provide.	effect-ts::optional-services
Что такое scoped layer?	Layer, чей конструктор использует Scope для ресурса с finalizer-ом; ресурс живёт столько же, сколько scope слоя.	effect-ts::scope
Что делает Effect.acquireRelease?	Открывает ресурс и регистрирует finalizer, который выполнится при закрытии Scope даже после ошибки или прерывания.	effect-ts::scope
Зачем в scoped layer для фонового процесса нужен forkScoped?	forkScoped привязывает fiber к Scope сервиса, чтобы он жил вместе с сервисом и корректно прерывался при закрытии.	effect-ts::scope
Что такое ManagedRuntime?	Долгоживущий runtime, который строит Layer-граф один раз, запускает много Effect-программ и умеет закрывать ресурсы через dispose.	effect-ts::managed-runtime
Когда ManagedRuntime особенно нужен?	Когда есть много запусков из внешнего фреймворка или несколько entry points, и нельзя пересобирать Layer-граф на каждый вызов.	effect-ts::managed-runtime
Зачем вызывать runtime.dispose()?	Чтобы закрыть Scope runtime: выполнить finalizer-ы, закрыть ресурсы и остановить forkScoped-фиберы.	effect-ts::managed-runtime
Что такое MemoMap в Layer?	Кеш построенных Layer-ов, благодаря которому одна и та же Layer-ссылка строится один раз в рамках графа или runtime.	effect-ts::memo-map
По какому ключу Effect мемоизирует Layer?	По ссылке на объект Layer, а не по тегу сервиса и не по параметрам фабрики.	effect-ts::memo-map
Как гарантировать один экземпляр параметризованного Layer-а?	Создать Layer один раз, сохранить в переменную и переиспользовать эту же ссылку в dependencies/mergeAll.	effect-ts::memo-map
Почему Layer-моки лучше vi.mock для Effect-программы?	Подмена идёт через типобезопасный DI-граф, без хрупкого мокания глобального fetch или ESM-модулей.	effect-ts::testing
О чём сигналит частое использование Layer.mock для одного сервиса?	Сервис, вероятно, слишком большой и его стоит разбить по ответственности на меньшие сервисы.	effect-ts::testing
Главный критерий: брать зависимость в конструкторе или методе?	Если значение глобальное и живёт весь runtime — брать в конструкторе. Если меняется на каждый запрос/операцию — брать в методе.	effect-ts::services::rule
Главный навык темы Services и Layer?	Видеть зависимости как часть типа R, собирать их через Layer-граф один раз и подменять реализации на границах программы.	effect-ts::services::summary
