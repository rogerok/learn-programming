# Структурная типизация

> [!info] Место в маршруте
> Это глава source-oriented трека Effective TypeScript. Каноническая основа: [[../basics/code-basic/structural-typing|структурная типизация]]. Общий маршрут: [[../MOC|TypeScript MOC]].

TypeScript использует **структурную** (duck typing) типизацию: совместимость типов определяется по **форме** (составу полей), а не по имени типа.

---

## Когда структурная типизация отключается

В классах с **приватными полями** структурная типизация превращается в **номинальную**: два класса считаются несовместимыми, даже если их поля идентичны.

```ts
class User {
  private type: string = "user";
}

class Admin {
  private type: string = "user";
}

const x: User = new User();
const b: Admin = x; // ❌ Error — разные классы, разные private
```

---

## Совместимость функций с разным числом перегрузок

TypeScript при проверке совместимости функций ищет **хотя бы одну перегрузку**, которая удовлетворяет требованиям.

```ts
const EMPTY_REF = Symbol("empty ref");

type MaybeEmptyRefCreator = {
  (): typeof EMPTY_REF;
  <T>(x: T): { value: T };
};

type TransparentWrapper = <A>(x: A) => A;

declare const refWrapper: MaybeEmptyRefCreator;

const wrap: TransparentWrapper = refWrapper;
// TypeScript принимает перегруженное объявление целиком.
```

Этот результат — особенность сравнения **набора overload signatures**. Из него нельзя заключать, что произвольная функция с обязательным аргументом может вызываться без аргументов или присваиваться типу `() => R`.

```ts
const one = (x: number): number => x;

// Error: target signature provides too few arguments
const zero: () => number = one;
```

Без overloads безопасно обратное направление: функция, которой нужно меньше аргументов, может использоваться там, где вызывающая сторона передаст больше — лишние аргументы будут проигнорированы.

```ts
const noArgs = (): number => 0;
const acceptsOne: (x: string) => number = noArgs; // OK
```

Это правило количества параметров не заменяет variance: для совпадающих позиций типы параметров по-прежнему проверяются контравариантно при `strictFunctionTypes`, а возврат — ковариантно.

---

## Проверяемое правило

> Для обычной source-функции обязательных параметров должно быть не больше, чем допускает target-сигнатура. Overload set проверяется по отдельным правилам, поэтому совместимость всего набора нужно подтверждать на реальных call sites, а не переносить на каждую overload signature.
