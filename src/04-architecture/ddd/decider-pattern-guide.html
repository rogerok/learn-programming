D/E Decider Field Guide

Functional Event Sourcing

Паттерн Decider

Ты отделяешь решение от изменения состояния. Команда и текущее состояние входят в decide. Функция возвращает события или доменную ошибку. evolve строит следующее состояние по событию. initial задаёт точку старта.

01 / Ментальная модель

Запрос, факт, память

Пользователь просит систему что-то сделать. Домен проверяет инварианты. Система записывает факты. Текущее состояние служит компактной памятью для следующего решения.

Decider хранит правила одной границы согласованности в трёх элементах: начальном состоянии, функции решения и функции перехода.

Command / команда

Намерение в повелительной форме

PlaceReservation, CheckInGuest, CancelReservation.

  • Команда просит изменить систему.
  • Домен может отклонить запрос.
  • Команда содержит данные намерения, а не результат.

Event / событие

Факт в прошедшем времени

ReservationPlaced, GuestCheckedIn, ReservationCancelled.

  • Событие фиксирует принятый доменом факт.
  • Записанный факт не меняют. Ошибку исправляют новым событием.
  • Событие несёт данные, нужные для восстановления состояния.
Command просьба
→
decide проверка правил
→
Event[] новые факты

State + Event → evolve → State. Новый state участвует в следующем решении.

Область ответственности: один Decider обслуживает один поток событий и одну границу согласованности. Если правило требует атомарно проверить две сущности, сначала проверь границу агрегата. Не соединяй потоки внутри decide скрытым чтением из БД.

02 / Анатомия

Каждый элемент отвечает на один вопрос

Переключай вкладки. В таблице указаны входы, допустимая работа, запреты, момент вызова и способ проверки.

initial: State

Состояние до первого события. Оно должно выражать реальную стартовую фазу домена.

ВходНет входа. Часто это значение или фабрика значения.
РезультатВалидный State, например { _tag: "NotPlaced" }.
КогдаПеред replay пустой истории и при создании нового потока.
РазрешеноКонстанта, пустые коллекции, доменные значения по умолчанию.
ЗапрещеноЧтение БД, текущее время, случайные ID, сетевой запрос.
Проверкаreplay([]) === initial. Первая допустимая команда работает на этом состоянии.

decide(command, state)

Функция принимает бизнес-решение. Она проверяет инварианты и описывает результат событиями.

ВходТипизированная Command и текущий State.
РезультатEvent[] при успехе или типизированная доменная ошибка.
КогдаОдин раз на попытку обработать команду, после replay.
РазрешеноПроверка правил, вычисление полей события, Clock и Random как явные зависимости.
ЗапрещеноЗапись в БД, публикация сообщений, мутация state, HTTP, скрытые глобальные зависимости.
ПроверкаGiven history, When command, Then events или ошибка.
Канон и Effect: исходная формула задаёт чистую функцию Command → State → Event list. Вариант урока возвращает Effect, чтобы получить время через Clock и выразить ошибку в типе. Сохраняй детерминизм: один state, одна command и одинаковые зависимости должны давать одинаковый результат.

evolve(state, event)

Функция материализует уже принятый факт. Она не решает, разрешён ли этот факт.

ВходТекущий State и одно событие.
РезультатСледующий State.
КогдаДля каждого события при replay и после выпуска новых событий.
РазрешеноКопирование нужных полей, арифметика, смена тега состояния.
ЗапрещеноClock, Random, I/O, проверка команды, публикация, мутация входного state.
ПроверкаОдин и тот же набор событий даёт один и тот же state.
Политика повреждённой истории: урок игнорирует событие в невозможном состоянии. Такой no-op может скрыть повреждение потока. Для своего проекта выбери политику явно: fail fast при нарушении последовательности, валидируй поток на границе или документируй безопасный no-op. Неизвестные версии событий обрабатывай upcaster-ом или миграцией. 
type Decider<Command, State, Event, Error> = {
  readonly initial: State;
  readonly decide: (
    state: State,
    command: Command,
  ) => Effect.Effect<ReadonlyArray<Event>, Error>;
  readonly evolve: (state: State, event: Event) => State;
};

03 / План применения

От предметной области до production

Первые пять шагов создают доменную модель. Последние шаги подключают инфраструктуру. Граница видна в коде: Decider не знает, где лежит поток событий.

Домен

Назови границу

Выбери сущность или процесс, чьи правила должны выполняться атомарно. Один ID потока связывает его историю.

Домен

Опиши язык

Команды назови глаголами намерения. События назови фактами в прошедшем времени. Ошибки назови причинами отказа.

Домен

Смоделируй State

Оставь данные, нужные следующему решению. Используй tagged union для фаз. Не копируй read-model.

Домен

Напиши decide

Разбери все команды. Проверь инварианты. Верни события или доменную ошибку. Исчерпывающий match ловит пропущенную ветку.

Домен

Напиши evolve и initial

Примени каждый тип события. Не обращайся к сервисам. Проверь replay на полной истории и на пустом потоке.

Application layer

Собери handler

Загрузи события с версией, восстанови state, вызови decide, затем добавь новые события с expected version.

Infrastructure

Защити запись

Event Store проверяет optimistic concurrency. При конфликте application layer решает, повторить команду или вернуть конфликт.

Read side

Построй проекции

Подписчики превращают события в модели для UI и поиска. Проекция не участвует в решении Decider.

const handle = (streamId, command) =>
  Effect.gen(function* () {
    const { events: history, version } = yield* eventStore.read(streamId);
    const state = history.reduce(decider.evolve, decider.initial);
    const newEvents = yield* decider.decide(state, command);

    yield* eventStore.append(streamId, version, newEvents);
    return newEvents;
  });
Почему expected version нужен: два обработчика могут прочитать одну версию и принять несовместимые решения. Event Store разрешает одну запись. Второй обработчик получает конфликт вместо тихого нарушения инварианта.

04 / Симулятор

Проведи бронь через Decider

Нажми команду. Симулятор вызовет decide, добавит событие в историю и применит evolve. Невалидная команда вернёт ошибку и не изменит историю.

Current state

NotPlaced Бронь ещё не создана.
Ожидание команды.

Append-only log

  1. История пуста. Начни с PlaceReservation.
Проверь инвариант: после ReservationCancelled или GuestCheckedOut ни одна команда не должна породить событие. Попытка останется в журнале интерфейса как ошибка, но event stream не изменится.

05 / Выбор

Decider окупается при сложных решениях

Отметь свойства задачи. Инструмент даст рекомендацию. Он помогает отсеять CRUD, где журнал событий добавит стоимость без пользы.

Заполни признаки Рекомендация появится после первого выбора.

Хороший кандидат

Заказ, платёж, бронирование

Фазы, запреты переходов, компенсации, аудит и конкурирующие команды.

Возможен без Event Store

Сложная state machine

Те же decide и evolve можно использовать с обычным хранением state. Паттерн не требует Event Sourcing.

Плохой кандидат

Справочник без правил

Экран редактирует название и описание. Обычная модель и транзакция дадут меньше кода.

06 / Проверка поведения

Тесты читаются как разговор с доменом

Выбери сценарий. Given задаёт прошлые события, When задаёт команду, Then фиксирует новые события или отказ. База данных и HTTP в таком тесте не участвуют.

GivenПустая история []
WhenPlaceReservation
Then[ReservationPlaced]
const verify = (history, command, expected) => {
  const state = history.reduce(decider.evolve, decider.initial);
  const result = runDecideWithFixedClock(state, command);
  expect(result).toEqual(expected);
};

Тестируй decide

  • Каждый разрешённый переход.
  • Каждый запрет и точный тип ошибки.
  • Содержимое и порядок нескольких событий.
  • Границы чисел, дат и лимитов.

Тестируй evolve и replay

  • Пустую и полную историю.
  • Перенос полей между фазами.
  • Детерминизм повторного replay.
  • Выбранную политику некорректной последовательности.

07 / Границы

Типичные ошибки проектирования

Открой пункт, чтобы увидеть симптом и исправление.

decide пишет в базу или отправляет сообщение

Риск: повторный вызов создаст побочный эффект до фиксации событий. Тест потребует инфраструктуру.

Исправление: decide возвращает данные. Application layer сохраняет события. Подписчик выполняет внешнюю реакцию после записи.

evolve проверяет бизнес-правила

Риск: старое событие может перестать реплеиться после изменения нового правила.

Исправление: decide решает, допустим ли новый факт. evolve трактует уже записанный факт по его версии.

State повторяет экран или таблицу

Риск: Decider накапливает поля, которые не нужны решениям, и связывается с UI.

Исправление: State хранит данные для будущих инвариантов. Отдельная проекция готовит данные для чтения.

Время читается через Date.now внутри decide

Риск: один ввод даёт разные события. Тест зависит от часов машины.

Исправление: передай время в команду после проверки доверенной границы или используй Clock как внедряемую зависимость Effect.

События редактируют или удаляют

Риск: аудит и replay перестают объяснять прошлые решения.

Исправление: добавь компенсирующее событие. Для изменения схемы используй версию события, upcaster или контролируемую миграцию.

Пропущена optimistic concurrency

Риск: две команды проходят проверку на одном state и нарушают инвариант при записи.

Исправление: append принимает ожидаемую версию потока. Конфликт становится явным результатом application layer.
